# 工业相机人脸识别上位机 —— 编译与部署说明

基于 Qt6 / MSVC2022，对接海康 MVS 工业相机，使用 ncnn 部署 SCRFD + ArcFace，
OpenCV 做预处理，识别结果与日志写入 MySQL。

---

## 一、工程文件结构

```
<项目根目录>\
├─ QT_Face.pro              qmake 工程文件（含 OpenCV / ncnn / QtSql 配置）
├─ opencv.pri               OpenCV 依赖配置
├─ ncnn.pri                 ncnn 依赖配置

├─ models/                  ncnn 模型文件（已含转换好的模型 + 转换脚本，见 models/README.md）
```

### 整体流水线对应关系

| 需求 | 实现位置 |
|---|---|
| 1 海康采集 | `cameraManager.cpp`（SDK 回调转 QImage） |
| 2 OpenCV 预处理 | `imagepreprocess.cpp`（letterbox / 亮度 / 清晰度） |
| 3 SCRFD 检测 | `facedetector.cpp`（ncnn，框 + 5 关键点） |
| 4 人脸对齐裁剪 | `facealigner.cpp`（112×112） |
| 5 ArcFace 512 维特征 | `faceextractor.cpp`（ncnn，L2 归一化） |
| 6 特征入库 / 注册 / 比对 | `facedatabase.cpp` + `facepipeline.cpp` |
| 7 阈值 + 识别输出 | `appconfig.cpp`（matchThreshold）+ `facedatabase.cpp#identify` |
| 8 界面显示 + 日志入库 | `mainwindow.cpp` + `facedatabase.cpp#insertLog` |

## 三、编译步骤

1. 用 **Qt Creator** 打开 `<项目根目录>\QT_Face.pro`。
2. 选择套件 **Desktop Qt 6.12.0 MSVC2022 64bit**（必须 64 位）。
3. 确认 `config.ini` 中 `[Database]` 的账号密码、模型路径正确。
4. 构建（Debug 或 Release）。构建完成后 `deploy-runtime.ps1` 会自动把
   Qt / ncnn / MVS / OpenCV 运行时、模型与 `config.ini` 拷到输出目录；
   若源码目录里还没有 `config.ini`，脚本会改用 `config.ini.example` 模板生成一份
   （需自行补齐数据库账号与口令）。

命令行构建示例：

```powershell
cd <项目根目录>
mkdir build; cd build
qmake ..\QT_Face.pro
nmake            # 或 jom
```

## 四、依赖部署步骤（目标机器）

把构建输出目录（含 exe）整体复制到目标机后，确认包含：

- `QT_Face.exe`
- `config.ini`、`models/`（模型文件）、`sql/`（初始化与迁移脚本）、`docs/`（部署说明）
- Qt 运行时：`Qt6Core.dll Qt6Gui.dll Qt6Widgets.dll Qt6Sql.dll`
  以及 `platforms/qwindows.dll`、`sqldrivers/qsqlmysql.dll`
- MySQL 客户端库：`libmysql.dll`（QMYSQL 驱动运行期依赖，deploy 脚本会自动拷贝）
- `ncnn.dll`
- OpenCV：`opencv_world500.dll`（Debug 为 `opencv_world500d.dll`）+ `opencv_videoio_*.dll`
- MVS 运行时：`MvCameraControl.dll` 及 `ThirdParty/`
- MSVC 运行库（或安装 VC++ 2015-2022 Redistributable）

以上由 `deploy-runtime.ps1` 自动完成。

当前工作区的权威部署输出为 `build/verify/release`（已含 exe、DPAPI 版
`config.ini`、`models/`、`sql/`、`docs/`、`tools/` 与全部运行时）；`build/`
下的其余目录只是构建/自检产物，不作为交付物。

### 跨机器移植检查清单

1. 目标机为 Windows x64；不需要重新安装 Qt/OpenCV/ncnn 也可以直接运行已部署目录。
2. 目标机如需编译：必须安装与工程一致的 Qt 6.12.0 MSVC x64、OpenCV 5.0.0 x64、
   MSVC x64 工具链和海康 MVS SDK，并按实际安装路径调整 `opencv.pri`、`QT_Face.pro`。
3. `config.ini` 与 `QT_Face.exe` 同目录，`models/` 原样保留。不要更换模型文件。
4. MySQL 8.0.x 已启动，`face_db` 已完成新库初始化或旧库迁移，
   `face_schema_meta.schema_version = 1`。
5. 使用非 root 运行账号时，按上一节授予最小权限；修改人员使用单独的
   MySQL 管理账号。
6. 确认 3306 端口、账号 host、防火墙和字符集 `utf8mb4` 配置正确。
7. 启动后确认状态栏显示模型和数据库初始化成功，再检查相机、注册、识别和日志。

## 五、MySQL 驱动与账号

Qt6 官方安装包默认不含 `QMYSQL` 驱动（无 `sqldrivers/qsqlmysql.dll`），
没装驱动时运行会在状态栏报“未找到数据库驱动 QMYSQL”。

### 本机现状（已处理）

- 驱动已按 Qt 6.12.0 msvc2022_64 编译好，放在
  `C:\Qt\6.12.0\msvc2022_64\plugins\sqldrivers\qsqlmysql.dll`，
  构建时 `windeployqt` 会自动把它拷到输出目录的 `sqldrivers\`。
- 驱动还依赖 MySQL 客户端库 `libmysql.dll`（取自
  `C:\Program Files\MySQL\MySQL Server 8.0\lib`），`deploy-runtime.ps1`
  最后一步会自动查找并拷贝。

### 换机器 / 换 Qt 版本时重建驱动

Qt 6.12 源码里 SQL 驱动插件只有 CMake 工程，本工程用的做法是：

1. 从 `qtbase` 的 `v6.12.0` 分支取 `src/plugins/sqldrivers/mysql/` 下的
   `main.cpp`、`qsql_mysql.cpp`、`qsql_mysql_p.h`、`mysql.json`；
2. 用本机 MySQL 8.0 的头文件与导入库（`include/`、`lib/libmysql.lib`）写一个最小
   qmake 工程（本机留存的工程在 `build/qsqlmysql/mysql/mysql.pro`）。关键两点：
   `QT += core sql sql-private`，以及 `DEFINES += QT_PLUGIN`（缺这个宏 moc 会报 C2491）；
3. `qmake mysql.pro && jom`，把生成的 `qsqlmysql.dll` 放到 Qt 的
   `plugins\sqldrivers\` 目录，并保证运行目录有 `libmysql.dll`。

### 备选：改用 ODBC

装好 MySQL ODBC 驱动后，把 `config.ini` 的 `driver` 改成 `QODBC`，连接串写成
`DRIVER={MySQL ODBC 8.0 Unicode Driver};SERVER=...;PORT=...;DATABASE=...;UID=...;PWD=...`
（`facedatabase.cpp` 目前按 QMYSQL 的 `setHostName/setPort` 写法实现，改 ODBC 需调整连接参数）。

### 账号、建库与旧库升级

`config.ini` 的 `[Database]` 必须配置本机 MySQL 真实可用的运行账号（推荐
`face_app`），否则状态栏会报 `Access denied for user '<账号>'@'localhost'`，
人脸模块整体初始化失败。程序不内置默认数据库账号：找不到 `config.ini` 时会
直接提示“找不到配置文件”，不会静默退回某个内置账号。

- 新机器首次部署建议由管理员执行：

```bat
cmd /c "mysql -u root -p < sql\schema.sql"
```

- 从旧版本升级时先备份数据库，再执行：

```bat
cmd /c "mysqldump -u root -p face_db > face_db_backup.sql"
cmd /c "mysql -u root -p < sql\migrate_personnel_source.sql"
```

- 旧表结构升级与缓存触发器创建统一由管理员执行
  `sql\migrate_personnel_source.sql` 完成，需要 `CREATE / ALTER / REFERENCES /
  TRIGGER` 权限；程序运行账号不参与建表和改表，也不需要任何 DDL 或
  `TRIGGER` 权限。
- 人员主数据只由 MySQL 维护。程序只读取 `face_employee`，只向
  `face_feature` 写入特征，并追加 `face_log`。
- `cacheSyncIntervalMs` 控制程序检查人员缓存版本号的周期，默认 1000ms。
  MySQL 中新增、改名、停用、启用或删除人员后，无需重启程序。

#### 旧库升级后的行为差异

从旧版本升级到当前版本后，以下两点操作习惯必须同步调整，否则会误判程序故障：

1. **人员必须由管理员先在 MySQL 建好**。旧版程序在注册时会顺带往
   `face_employee` 插入人员行；现在程序只读取人员、只向 `face_feature` 追加特征。
   工号不存在或 `is_active=0` 时注册会被拒绝（提示“工号 … 不在 MySQL
   face_employee 中”/“已停用”），不是程序坏了。
2. **改库后不再需要重启程序**。旧版直接改 MySQL 后必须重启，否则内存缓存不更新，
   会出现“已删除人员仍被识别”的幽灵特征；现在 `face_employee` / `face_feature`
   的增删改会由 6 个缓存触发器递增 `face_cache_revision`，程序按
   `cacheSyncIntervalMs`（默认 1000ms）轮询刷新，约 1 秒内自动生效。

迁移完成后的推荐运行账号权限如下（单机示例使用 `localhost`）：

```sql
CREATE USER 'face_app'@'localhost'
IDENTIFIED BY '替换成高强度密码';

GRANT SELECT ON face_db.face_employee TO 'face_app'@'localhost';
GRANT SELECT, INSERT, DELETE ON face_db.face_feature TO 'face_app'@'localhost';
GRANT SELECT, INSERT ON face_db.face_log TO 'face_app'@'localhost';
GRANT SELECT ON face_db.face_cache_revision TO 'face_app'@'localhost';
GRANT SELECT ON face_db.face_schema_meta TO 'face_app'@'localhost';
FLUSH PRIVILEGES;
```

如果 MySQL 与程序不在同一台机器，应将 `localhost` 替换为具体来源网段或终端 IP。

**不要**给运行账号授予 `TRIGGER` 或 `SET_USER_ID`。`SET_USER_ID` 允许创建指定
任意 `DEFINER` 的触发器或存储程序，等于把提权到 `root` 的能力交给运行账号，
会让 DPAPI 保护口令的意义大打折扣。6 个缓存触发器由管理员执行
`sql\migrate_personnel_source.sql` 创建，程序不检查也不补建。

触发器健康检查由独立的只读脚本完成，由管理员或维护任务执行：

```bat
cmd /c "mysql -u root -p -D face_db < sql\check_cache_triggers.sql"
```

输出中 `state=缺失` 的触发器，由管理员重新执行
`sql\migrate_personnel_source.sql` 修复（该脚本会 DROP 后重建全部 6 个触发器）。
确实需要自动修复时，应另建一个独立的特权维护进程，而不是给应用数据库账号提权。

当前运行账号、DPAPI 实施状态和给复核 agent 的检查清单位于：

```text
docs\DB_RUNTIME_ACCOUNT_AND_DPAPI.md
```

#### Windows DPAPI 口令保护

推荐用 Windows DPAPI 保存 MySQL 运行口令，配置文件中只保留密文：

```ini
[Database]
user=face_app
password=
passwordDpapi=AQAAANCMnd8BFdERjHoAwE/Cl+sBAAAA...
```

首次设置或修改 MySQL 口令时，必须由**实际启动 QT_Face.exe 的 Windows 用户**
执行：

```powershell
.\tools\set-db-password-dpapi.ps1 -ConfigPath .\config.ini
```

脚本会安全提示输入口令，使用 `DPAPI CurrentUser` 范围加密，清空明文
`password`，写入 `passwordDpapi`。脚本不会在控制台或配置文件中打印明文口令，
也不会生成包含旧明文口令的备份文件。

DPAPI 密文与当前 Windows 用户绑定。把配置文件复制到其他电脑或换用另一个
Windows 用户启动时，程序会明确提示 DPAPI 解密失败，不会静默回退到空口令。
如果仍保留旧版明文 `password`，程序会继续兼容读取；完成 DPAPI 迁移后应清空
该字段。

## 六、运行流程

1. 启动程序 -> 自动查找相机 -> 选择设备 -> 打开相机 -> 开始采集。
2. 界面左侧实时显示画面；识别开启时，会在人脸框上绘制框、5 个关键点与标签
   （绿色=识别成功，红色=未知/未匹配）。
3. **维护人员**：在 MySQL 的 `face_employee` 中新增或修改人员。
   `is_active=1` 表示启用，`is_active=0` 表示停用；程序不会创建或覆盖人员主数据。
4. **注册**：先在 MySQL 中准备好工号，再让目标人脸出现在画面中
   （或“打开本地图片”载入照片），填写工号，姓名由程序从 MySQL 自动带出，
   点“注册人脸”。程序取当前帧中面积最大的人脸，质量合格则提取特征写入
   `face_feature`。不存在或已停用的人员会被拒绝注册。
5. **识别**：连续采集时，Pipeline 每 200ms 处理一帧，提取特征后与启用人员的特征做
   余弦相似度比对，超过阈值即判为匹配，并把结果（工号/相似度/时间/图片路径）
   写入 `face_log`，同时刷新界面日志表。
   同一个目标（工号，未识别的按“未识别”算）3 秒内只写一条日志、只存一张抓拍图，
   否则一直对着镜头就会以帧率级别无限写库、写图（冷却时间见 `facepipeline.cpp`
   的 `kLogCooldownMs`）。
6. 质量不合格（模糊/过暗/过曝/人脸过小）的人脸会被直接丢弃，不参与识别与入库，
   界面上以红色 `LowQuality` 标注。
7. **删除人员**：`DELETE FROM face_employee WHERE employee_no='工号'` 会经外键
   `fk_feature_employee`（`ON DELETE CASCADE`）**连带删除该工号的全部
   `face_feature` 模板**（可能一次删掉 5 张），`face_log` 历史记录保留。
   只想让某人暂时无法被识别时，请把 `is_active` 置 0，不要删人员行。

### 人员注册流程

#### 1. 前置条件

人员主数据由 MySQL 管理，程序不会自动创建人员。注册前先在
`face_employee` 中新增人员，或将已有人员重新启用：

```sql
INSERT INTO face_db.face_employee
    (employee_no, name, department, is_active)
VALUES
    ('10001', '张三', '生产部', 1)
ON DUPLICATE KEY UPDATE
    name = VALUES(name),
    department = VALUES(department),
    is_active = 1;
```

必须满足：

- `employee_no` 已存在且在程序中唯一；
- `is_active = 1`；
- 姓名和部门填写正确，程序只读取，不会覆盖这些字段。

#### 2. 界面操作

1. 启动 `QT_Face.exe`，确认状态栏显示模型和数据库初始化成功。
2. 选择摄像头，点击“打开相机”和“开始采集”；没有摄像头时也可以点击
   “打开图片”载入一张本地照片。
3. 在“工号”输入框中填写工号，例如 `10001`。
4. 按 `Tab` 或点击其他控件，姓名会从 MySQL 自动读取并显示。姓名输入框为只读。
5. 让待注册人员正对镜头，保持光线均匀、画面清晰。多人同时出现时程序只取
   当前画面中面积最大的人脸，因此建议注册时画面中只保留一人。
6. 点击“注册人脸”，等待右侧操作反馈和状态栏显示注册结果。
7. 成功后会看到类似提示：

```text
注册成功: 10001 张三，该工号模板 1/5 张，库内共 N 人
```

每次点击只采集一张模板。同一工号最多保留 5 张模板，可以继续采集正面、左侧、
右侧、抬头、低头等不同角度。超过 5 张时程序会自动淘汰最旧的一张。

#### 3. 程序内部处理顺序

```text
校验工号存在且 is_active=1
        ↓
读取当前帧或本地图片
        ↓
SCRFD 检测人脸和 5 个关键点
        ↓
选择面积最大的人脸
        ↓
质量检查
        ↓
5 点对齐为 112x112
        ↓
ArcFace 提取并 L2 归一化 512 维特征
        ↓
事务写入 face_feature，并裁剪超限模板
        ↓
刷新内存特征缓存
        ↓
保存注册人脸图
```

注册证件图保存在：

```text
captures\register\yyyyMMdd\工号_时间.jpg
```

注册过程只写入 `face_feature` 和注册图片，不写入 `face_log`。`face_log` 只记录
运行期间实际发生的识别结果。

#### 4. 注册质量要求

默认阈值来自 `config.ini` 的 `[Quality]`：

| 项目 | 默认值 | 说明 |
|---|---:|---|
| `minFaceWidth` | 60 像素 | 人脸框宽度低于该值视为过小 |
| `minBlurScore` | 100 | Laplacian 方差低于该值视为模糊 |
| `minBrightness` | 40 | 人脸区域平均亮度过低视为过暗 |
| `maxBrightness` | 220 | 人脸区域平均亮度过高视为过曝 |

质量不合格时不会写入数据库，程序会提示具体原因。

#### 5. 注册结果检查

查询某个工号的模板数量：

```sql
SELECT employee_no, COUNT(*) AS template_count
FROM face_db.face_feature
WHERE employee_no = '10001'
GROUP BY employee_no;
```

确认注册图片已生成：

```powershell
Get-ChildItem .\captures\register -Recurse -Filter "10001_*.jpg"
```

#### 6. 常见失败原因

| 提示 | 处理方式 |
|---|---|
| 工号不在 `face_employee` 中 | 先在 MySQL 新增人员，确认工号无误 |
| 人员已停用 | 将 `is_active` 改为 `1`，程序约 1 秒内同步 |
| 未检测到人脸 | 调整光照、距离和拍摄角度，确保完整人脸进入画面 |
| 人脸质量不合格 | 按提示处理模糊、过小、过暗或过曝问题 |
| 特征写入失败 | 检查 MySQL 连接、写权限和 `face_feature` 外键 |
| 注册成功但图片不存在 | 检查运行目录写权限和 `captures` 目录 |

### 没有工业相机时：用电脑自带摄像头

「查找相机」会把本机 UVC 摄像头一起列出来，形如 `[本机摄像头] USB 摄像头 0`
（工业相机显示为 `[工业相机] 型号 (序列号) - IP`），选中后「打开相机 / 开始采集」
走同一条显示、识别、录像、日志通路。区别是：

- 曝光/增益/帧率/SCPD/像素格式这组参数对 UVC 无效，界面会自动禁用；
- 没有软触发（本地摄像头是连续采集）；
- 录像帧率取驱动上报值，驱动不给（常见）时按 25 fps 写。

采集用 OpenCV `VideoCapture`（Windows 下默认 MSMF 后端，失败退回 DSHOW），
默认请求 1280×720。摄像头被其它程序（含本程序的另一个实例）占用时会打不开，
状态栏会给出提示。

## 七、编译 / 运行排坑清单

| 现象 | 原因与解决 |
|---|---|
| `MVS headers not found` / `MVS runtime not found` | 未安装海康 MVS，或路径不在默认位置；改 `QT_Face.pro` 中的 `MVS_SDK`。 |
| `ncnn headers not found` | `ncnn.pri` 中 `NCNN_ROOT` 路径不对，或 `thirdparty` 未随工程拷贝。 |
| 链接报 `LNK2019 ncnn::...` | 未链接 `ncnn.lib`，或 ncnn.dll 未放到 exe 目录。 |
| 启动即退出、找不到 `ncnn.dll` | 运行目录缺少 `ncnn.dll`（用 deploy 脚本或手动拷贝）。 |
| `未找到数据库驱动 QMYSQL` | 运行目录 `sqldrivers\` 下缺 `qsqlmysql.dll`。本机 Qt 插件目录里已有该驱动，`windeployqt` 会带过来。 |
| 改了 `config.ini` 但程序行为没变 | 程序读的是 **exe 同目录**的 `config.ini`，那份只在**链接之后**由 `deploy-runtime.ps1` 更新。改完要在 Qt Creator 里「重新构建」(Rebuild)，或手动把它拷到 exe 目录。 |
| 驱动在但连不上 | 先看报错文本：`Access denied` 是账号密码不对（改 `config.ini`）；`libmysql.dll` 缺失会让驱动加载失败，检查运行目录。 |
| 连不上 MySQL | 检查 `config.ini` 的 host/port/user/password；确认 MySQL 服务已启动、允许远程；防火墙放行 3306。 |
| 中文乱码 | 数据库/表必须 `utf8mb4`；`schema.sql` 已指定。 |
| 注册/日志写入失败，无中文错误 | QtSql 报错文本在状态栏与 `qDebug` 输出中，配合 Qt Creator “应用程序输出”查看。 |
| 启动即弹“人脸识别初始化失败” | 提示文本会说明是模型没加载还是数据库连不上；模型问题见 `models/README.md` 第三节。 |
| 启动提示“数据库结构未迁移或版本无效” | 说明 `face_schema_meta.schema_version < 1`。由管理员执行 `sql\migrate_personnel_source.sql`；程序运行账号不会自动建表。 |
| 注册提示工号不在 `face_employee` | 先在 MySQL 维护人员，并确认 `is_active=1`；程序不会自动新增人员。 |
| MySQL 中改名/停用后程序未变化 | 检查 `face_schema_meta.schema_version=1`、6 个缓存触发器和 `cacheSyncIntervalMs`；正常情况下 1 秒左右自动刷新。 |
| 启动提示存在孤立特征 | 先修复 `face_feature.employee_no` 没有对应人员的记录，再启动程序。程序不会自动删除这类业务数据。 |
| Qt Creator 的 Issues 面板报 `use of undeclared identifier '_udiv128'` | clangd 代码模型的误报：Qt Creator 会给 clangd 传 `-U__clang__`，而 MSVC 14.5x 的 `__msvc_int128.hpp` 靠 `#ifdef __clang__` 判断是否调用 MSVC 专有的 `_udiv128/_div128`。不影响 MSVC 编译。工程里的 `.clangd` 用 `CompileFlags.Remove` 删掉这些 `-U__clang__*` 参数修掉了，不含任何绝对路径，克隆到任意目录都直接生效。 |
| 刷屏的第三方头文件告警：`ncnn/gpu.h` 的 `C4273 dll 链接不一致`、Qt 头文件的 `C4996 compressEvent 已弃用` | 都是第三方头文件自身的问题（ncnn 里 `create_gpu_instance` 的 friend 声明没带导出属性；`compressEvent` 在 Qt 6.12 已弃用）。工程用 `/external:anglebrackets /external:W0` 把用 `<>` 包含的头文件当外部头文件，构建输出已无这两类告警；自己源码（用 `""` 包含、或在自己的文件里调用弃用 API）的告警照旧。 |
| 检测框错位 / 相似度普遍很低 | 模型归一化或输出布局与预期不符，见 `models/README.md` 第二、三节。 |
| 识别时界面卡顿 | 确认 `config.ini` 中 `numThreads` 合理；Pipeline 已做 200ms 节流与丢帧。 |
| `opencv_world500d.dll` 缺失（Debug） | Debug 构建部署了 release DLL 或反之，检查 `deploy-runtime.ps1` 的配置分支。 |
| 录制视频报“编码器打不开” | OpenCV 的 `opencv_videoio_ffmpeg*.dll` 未部署；先试 AVI(MJPG)。 |
| 打开相机后参数写不进去（0x80000106） | 需先关闭自动曝光/增益；本工程 setExposure/setGain 已自动处理。 |
