# 风险登记与排障手册

## 1. 文档用途

本文记录当前人脸识别项目已知的运行风险、触发条件、影响、检查方法和恢复步骤。
以后现场出现异常时，先按本文定位，再决定是否修改代码。

更新时间：2026-10-17

验收范围：

- Windows x64 单机运行；
- 用途仅为人脸检测、注册和 1:N 身份识别；
- 不包含活体检测、门禁防作弊或无人值守安全认证。

## 2. 风险等级

| 等级 | 含义 |
|---|---|
| 高 | 正常使用会失败、数据损坏或产生严重安全问题，必须修复后才能交付 |
| 中 | 特定环境或维护误操作下会导致识别中断、缓存失效或难以回归定位 |
| 低 | 发生概率较低，或只影响附属功能，有明确恢复方式 |
| 接受 | 已明确不在项目范围，不作为缺陷 |

当前结论：在“仅用于人脸识别”的范围内，没有高等级阻塞项。

## 3. 风险登记

### R-01 更换工业相机或运行环境后的兼容性

| 项目 | 内容 |
|---|---|
| 等级 | 低 |
| 影响 | 更换相机型号、固件、MVS 版本或主机后，可能出现连接、触发或参数兼容问题 |
| 触发条件 | 更换工业相机硬件或运行环境 |
| 当前状态 | 海康 MVS 工业相机已实测跑通；UVC 摄像头也已实测 |

当前已验证工业相机能够完成设备枚举、连接和采集，并跑通识别链路。
更换设备或运行环境后建议复验：

1. 设备能被“查找相机”枚举；
2. 连续模式能稳定采集；
3. 软触发模式能够收到图像；
4. 曝光、增益、帧率和像素格式可以设置并回读；
5. 连续采集 30 分钟无明显掉线、卡顿或内存增长；
6. 关闭采集和断开相机时程序不崩溃。

相同硬件与相同软件环境下，当前风险为低。

### R-02 缓存触发器缺失会导致人员/模板变化不刷新

| 项目 | 内容 |
|---|---|
| 等级 | 中 |
| 影响 | MySQL 中人员改名、停用、启用、删除或模板变化后，程序仍可能使用旧缓存 |
| 触发条件 | 6 个触发器中的一个或多个被误删 |
| 当前状态 | 程序运行账号为纯 DML，不检查也不补建触发器 |

检查：

```bat
cmd /c "mysql -u root -p -D face_db < sql\check_cache_triggers.sql"
```

正常输出 6 行，`state` 全部为“存在”。

恢复：

```bat
cmd /c "mysql -u root -p < sql\migrate_personnel_source.sql"
```

迁移脚本会重建 6 个缓存触发器。该脚本需要管理员账号执行。

注意：不要给运行账号授予 `TRIGGER` 或 `SET_USER_ID`；这会扩大权限并引入
自定义 `DEFINER` 提权风险。

### R-03 缺少自动化回归测试

| 项目 | 内容 |
|---|---|
| 等级 | 中 |
| 影响 | 后续修改可能重新引入缓存、摄像头、数据库或识别链路问题 |
| 触发条件 | 修改源码后没有执行构建、启动和关键链路测试 |
| 当前状态 | 人工验证通过，但主工程没有正式测试目标 |

每次修改后至少执行：

1. 从当前提交全量构建 Release；
2. 使用 `face_app` 和 DPAPI 启动；
3. 检查 `face_schema_meta.schema_version = 1`；
4. 检查 6 个缓存触发器；
5. 验证注册、识别和日志写入；
6. 验证本机摄像头开始/停止采集和录像收尾。

### R-04 日志和抓拍图片会持续增长

| 项目 | 内容 |
|---|---|
| 等级 | 低 |
| 影响 | 长期运行占用磁盘，日志数量可能高于实际人员出现次数 |
| 触发条件 | 同一人员持续停留在镜头前；或大量未识别人员出现 |

当前行为：

- 同一工号每 3 秒最多写一条日志和一张抓拍图；
- 所有未识别人脸共用 `__unknown__` 冷却键；
- 多个未识别人脸在 3 秒内出现时，可能只记录其中一次；
- 当前没有自动清理或保留期限。

如果日志只用于辅助查看，可以接受。长期部署时应增加：

- 日志保留天数；
- 抓拍图片清理任务；
- 磁盘剩余空间监控。

### R-05 摄像头驱动卡死后的恢复

| 项目 | 内容 |
|---|---|
| 等级 | 低 |
| 影响 | 采集线程无法退出，摄像头不能正常关闭，需要重启程序 |
| 触发条件 | 摄像头掉线、驱动异常或 OpenCV/MSMF 读帧长时间阻塞 |

当前处理：

- 先等待采集线程退出；
- 超时后尝试 `terminate()`；
- 仍无法退出时保留线程对象，避免直接销毁运行中的 `QThread` 导致进程崩溃；
- 界面提示“已放弃关闭设备，请重启程序”。

现场处理：停止采集，关闭程序并重新启动。若重复出现，检查摄像头占用、USB
连接、驱动和曝光设置。

### R-06 DPAPI 密文与 Windows 用户绑定

| 项目 | 内容 |
|---|---|
| 等级 | 低 |
| 影响 | 更换 Windows 用户、重装系统或复制到其他机器后无法解密数据库口令 |
| 触发条件 | 当前用户与生成 `passwordDpapi` 的用户不一致 |

典型错误：

```text
数据库口令 DPAPI 解密失败（Windows 错误码 0x0000000d）
```

恢复：

1. 管理员重置 `face_app` 密码；
2. 用实际运行程序的 Windows 用户执行：

```powershell
.\tools\set-db-password-dpapi.ps1 -ConfigPath .\config.ini
```

3. 重新启动程序。

### R-07 配置文件未进入 Git

| 项目 | 内容 |
|---|---|
| 等级 | 低 |
| 影响 | 新机器没有 `config.ini`，程序无法直接使用现场参数 |
| 触发条件 | 新克隆仓库或直接复制源码但未复制运行配置 |

处理：

1. 从 `config.ini.example` 复制一份 `config.ini`；
2. 设置 `user=face_app`；
3. 在生产环境用 DPAPI 工具生成 `passwordDpapi`；
4. 不要提交 `config.ini`。

### R-08 模型产物不在 Git 仓库中

| 项目 | 内容 |
|---|---|
| 等级 | 低 |
| 影响 | 新环境构建成功但启动时模型加载失败 |
| 触发条件 | 没有按说明下载并转换模型 |

当前仓库只提交模型说明和转换脚本。`.param`、`.bin`、`.onnx` 等产物均被
`.gitignore` 排除，需要用户按 `models/README.md` 在本地生成，并随运行包部署。

确认文件：

```text
models\scrfd_500m.bin
models\arcface_mbf.bin
```

### R-09 静态照片可以识别

| 项目 | 内容 |
|---|---|
| 等级 | 接受 |
| 影响 | 照片或屏幕中的人脸可能通过识别 |
| 触发条件 | 当前识别链路没有活体检测 |

已确认项目用途仅为“识别人脸”，不承担防照片、防视频回放或门禁防作弊职责。
因此本项不按缺陷处理。

如果以后将项目用于门禁或考勤，必须重新立项增加活体检测，并重新进行安全验收。

## 4. 常见故障速查

### 启动提示“数据库结构未迁移或版本无效”

原因：`face_schema_meta.schema_version < 1`。

处理：

```bat
cmd /c "mysql -u root -p < sql\migrate_personnel_source.sql"
```

### 启动提示 `Access denied`

依次检查：

1. `config.ini` 的 `user` 是否为 `face_app`；
2. Windows 用户是否与生成 DPAPI 密文时一致；
3. `face_app` 是否仍存在；
4. MySQL 服务和 3306 端口是否正常；
5. MySQL 用户 host 是否匹配。

### 人员改名或停用后程序没有变化

依次检查：

1. `face_schema_meta.schema_version` 是否为 1；
2. 6 个缓存触发器是否都存在；
3. `face_cache_revision.revision` 是否在修改后递增；
4. `config.ini` 的 `cacheSyncIntervalMs` 是否合理；
5. 程序是否仍在运行旧缓存。

### 注册成功但注册图不存在

检查：

1. 界面是否出现“注册图未保存”提示；
2. 运行目录下的 `captures/register` 写权限；
3. 磁盘空间；
4. `employee_no` 是否包含特殊字符，新版本会自动转换文件名。

### 识别日志没有写入

检查：

1. 人脸是否通过质量门限；
2. 识别是否开启；
3. `face_app` 是否有 `face_log SELECT, INSERT` 权限；
4. 是否处于 3 秒冷却期；
5. 状态栏是否显示数据库错误。

### 摄像头无法关闭

1. 确认没有其他程序占用摄像头；
2. 停止采集后关闭程序并重启；
3. 检查 USB 连接和摄像头驱动；
4. 若反复出现，记录程序版本、摄像头型号和错误提示。

## 5. 日常维护清单

- 每周执行一次缓存触发器健康检查。
- 每月检查 `face_log` 数量、抓拍图片大小和磁盘剩余空间。
- 修改人员主数据后，现场确认程序约 1 秒内刷新。
- 更换 Windows 用户或机器后，重新执行 DPAPI 设置。
- 更新程序前先备份数据库和 `config.ini`。
- 修改源码后执行完整构建和至少一次注册/识别回归测试。
